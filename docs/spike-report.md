## 3. 게이트 판정
SPK-1~5는 실기기에서 동작했고 이후 본 개발(E1~)로 넘어갔다. 수치 기준 중 카메라 미리보기(639ms)·Firebase 왕복(944ms)·위치 첫 값(1.3초)은 2-1장의 실측으로 통과가 확인된다. **OCR 처리 시간(3초), 노포 앞 정확도(30m), 마커 1,000개 부하는 수치 기록이 없어 "미검증"** 상태다. 발표·QA 문서에 수치를 쓰려면 5장을 먼저 하라.

## 5. 재측정 절차 (사용자 또는 다음 에이전트, 기기 A에서)
진단 화면: 설정 > 앱 정보 5번 탭 > 개발자 도구 > 진단. 결과는 화면 값을 직접 옮겨 적어(현재 진단 화면에는 복사 버튼이 없다) 이 문서에 기록한다.
1. **지도**: 지도 탭 "마커 1,000개" → 표시된 ms와 체감, 인증 오류 문구 없음. 비행기 모드에서 앱이 죽지 않는지.
2. **카메라**: 미리보기 첫 화면 ms(목표 1초). "메모리로 촬영" 후 Device Explorer `files/`·`cache/`에 새 파일 없음. "파일로 촬영" 썸네일이 똑바로 보임.
3. **글자 인식**: `tools/test-images/test_receipt_live.html`을 PC 화면에 띄워 촬영 → 줄 수·ms(목표 3초 이내)·전화·결제일시 추출. 비행기 모드 반복, 연속 10회. 디버그 빌드의 "샘플 영수증/간판 이미지로 시험" 버튼 결과도 기록.
4. **위치**: 실외 3회·실내 3회 정확도, **실제 노포 문 앞**에서 가게 좌표까지 거리·정확도(→ 30m 판정 통과 여부). 모의 위치 앱 감지, "대략적 위치만" 안내, 15초 후 업데이트 해제.
5. **Firebase**: 가입/로그인 뒤 "쓰기 → 서버 읽기" 왕복 ms(목표 2초). 비행기 모드 쓰기 → 복귀 후 서버 반영.
6. **릴리스 APK**: 위 1~5를 릴리스에서 반복(R8 문제 없음). APK 크기 기록.
