## 5. 이번 기간에 발견·수정한 결함
| 결함 | 원인 | 조치 |
|---|---|---|
| 시험용 가게에서 인증 후 리뷰 화면이 안 뜸 | 상세 화면의 리뷰 ViewModel이 인증 전 상태를 유지 | 방문 기록 변화를 관찰해 자격 재계산, 인증 직후 "평점·리뷰 남기기" 버튼 추가 |
| 리뷰를 또 쓰면 이전 리뷰가 사라짐 | 가게당 문서 ID 1개 | 슬롯 방식(1~5)으로 여러 개 저장, 시험용 가게도 목록 저장 |
| 승급 연출이 도장 연출을 가림 | 결과 화면이 열리자마자 승급 대화상자 | 도장 → 폭죽 → 2.8초 뒤 승급 순서로 변경 |
| 리뷰 폭탄·위조 가능(QA 높음 2건) | 규칙에 개수·필드 검증 없음 | 규칙 강화·재배포, 오류 코드 `E_REVIEW_LIMIT` |
| 룰렛 동의 직후 첫 호출이 무시됨 | 동의 저장 전에 호출 | `agreeAndSpin`으로 순서 보장 |
| 인증 화면 시험 실패(`reviewIntentStoreId` 모의 없음) | 새 컨테이너 필드 | 시험 설정 보강 |
| 내 위치 버튼이 처음에만 이동 | 이동이 한 번만 실행 | 누를 때마다 이동, 빠른 위치(저전력 3초) 선반영 |

## 6. 회귀 점검 (기존 기능이 깨지지 않았는지)
- 전체 단위 테스트 291개 통과(칭호·리뷰·인증·동기화·AI·룰렛·충성도·QR 포함).
- 릴리스(R8) 빌드에서 AI 응답 파싱(kotlinx.serialization)·룰렛·번역 동작 확인.
- 카탈로그 재적재·시연용 패스포트·시험용 가게 생성 동작 확인.

## 7. 알려진 문제·한계 (미해결)
1. 리뷰 편집 중 고른 사진은 ViewModel 초안에 보관해 **화면을 돌려도 유지**(2026-10-21 수정). 앱 프로세스가 완전히 종료되면 사라짐(Bundle 용량 문제로 의도적).
2. 리뷰 목록이 사진 base64를 전부 읽음(썸네일 필드 필요) — 사진 많은 가게에서 메모리 사용↑.
3. `reviewCount`·`totalYears`는 서버 함수 없이는 위조 가능.
4. 스캔 연출의 형광펜 위치는 촬영 순간의 장면 기준이라 비스듬한 사진은 약간 어긋날 수 있음.
5. 단골 충성도 비교 대상은 앱에 들어 있는 시연용 예시 데이터(서울 270곳). 실제 서버 데이터 비교는 미구현.
6. AI 기능은 인터넷·키·API 한도에 의존(실패하면 `E_AI_FAILED` 안내).
7. 시연 장소를 옮기면 테스트 가게를 다시 만들어야 위치(30m) 시험이 가능.
8. 같은 영수증 두 번 사용 차단(E_RECEIPT_DUP)은 서버 판정이라 시험용 가게에서는 보이지 않음.
9. Google Places 사진(앱 자산 약 26MB)은 약관상 공개 배포 전 재확인 필요.

남은 위험·할 일
- **2026-11-02부터 AI Logic의 App Check 적용이 의무**(공식 문서). 그 뒤에는 App Check 제공자 또는 서버 프록시(Blaze 요금제)가 필요하다. 공개 APK는 Play Integrity를 통과하는지 검증하지 못했다.
- 이전 공개 APK에 들어 있던 Gemini 키는 **폐기 필요(사용자)**.
- 지금은 App Check 적용 해제 상태라 다른 앱이 이 프로젝트의 AI 무료 할당량을 쓸 수 있다.
- 번역은 소개글과 리뷰를 한꺼번에 보내 가게에 따라 30초 이상 걸릴 수 있다(아래 7장 알려진 문제에 추가).
- (수정) 번역이 느림: 글을 8개씩 묶어 동시에 요청하도록 바꿈(단위 테스트: 20개 → 8·8·4 세 묶음, 순서 유지 **PASS(자동)**). 실기기 소요 시간은 아래 K-04b에 기록.
