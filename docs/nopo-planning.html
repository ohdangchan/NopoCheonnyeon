Concept

한 줄 정의와 차별점

노포 천년 미식가는 내가 먹어 온 세월을 모으는 앱입니다. 별점 대신 업력을 점수로 씁니다. 1964년에 문을 연 설렁탕집에 가면 62년이, 1990년에 문을 연 분식집에 가면 36년이 내 패스포트에 쌓입니다. 합계가 1,000년이 되면 ‘천년 미식가’ 칭호를 받습니다.

맛집 앱이 “어디가 맛있나”에 답한다면, 이 앱은 “나는 지금까지 얼마나 오래된 맛을 먹어 봤나”에 답합니다. 평점과 리뷰도 남길 수 있지만, 그 가게를 방문 인증한 사람만 남길 수 있습니다. 그래서 이 앱의 평점은 “실제로 다녀온 사람의 평가”입니다.

제안앱 이름은 ‘노포 천년 미식가’를 그대로 쓰고, 도장 속에 千年(천년) 문양을 넣어 이름과 보상을 하나로 묶습니다.

Core loop

핵심 규칙: 세월을 모은다

  • 방문 인증 1회에 그 가게의 업력(올해 − 개업연도)만큼 세월이 쌓입니다.
  • 같은 가게는 처음 한 번만 세월을 올리고, 다시 가면 단골 횟수만 늘어납니다.
  • 가게가 문을 닫아도 이미 쌓은 세월은 그대로 남습니다.
  • 노포의 기준은 업력 30년 이상으로 둡니다. 공공 인증 제도의 기준과 같습니다.
  • 창업연도를 모르는 가게는 업력 30년(공식 지정 최소 기준)으로 계산하고 “업력 확인 중”으로 표시합니다.

도장 등급은 업력으로 정합니다

일반 도장업력 30~49년

붉은 도장업력 50~99년

금빛 도장업력 100년 이상

제안세월 합계는 가게마다 올해가 바뀌면 1년씩 늘어납니다. 이미 적립한 값은 인증한 날의 업력으로 고정하는 안을 기본으로 둡니다. 계산이 단순해지고 기록이 흔들리지 않습니다.

UX flow

화면 설계: 세 번 눌러 도장까지

수집 흐름의 핵심 화면은 다섯 개입니다. 지도에서 핀을 누르면 상세, 상세에서 인증, 인증이 끝나면 도장 연출, 마지막에 패스포트로 이어집니다. 주요 버튼은 모두 화면 아래쪽 엄지 영역에 둡니다. 로그인·리뷰·프로필 화면은 ‘평점·리뷰와 다른 미식가의 프로필’ 장에 있습니다.

UX 원칙적용 방식
세 번 안에 인증지도 핀 → 상세 → 인증하기. 중간에 로그인이나 설문을 끼우지 않습니다.
보상을 먼저 보여 주기상세 화면에 “인증하면 세월 +62년”을 먼저 노출해 눌러 볼 이유를 만듭니다.
빈 상태도 설계아직 비어 있는 도장 칸은 점선으로 두고 “다음에 갈 노포 자리”라는 문구를 붙입니다.
한 손 조작주요 버튼은 화면 하단 3분의 1 안에 둡니다.
읽기 쉬운 글자본문 14sp 이상, 글자와 배경 대비 4.5:1 이상을 기준으로 삼습니다.

Q6 · Verification

방문 인증: 영수증 먼저, 안 되면 30m 안 가게 사진

요청하신 규칙 그대로입니다. 영수증 인증은 위치를 전혀 쓰지 않고, 영수증이 없거나 인식되지 않을 때만 위치를 확인합니다. 가게에서 30m 안에 있으면 간판·메뉴판·출입문처럼 가게 이름이나 전화번호가 보이는 사진으로 대신 인증합니다.

왜 정확도도 30m 이하여야 하나

폰이 알려 주는 위치에는 “이 반경 안에 있을 확률이 약 68%”라는 정확도 값이 붙습니다. 정확도가 ±80m인 값으로 “가게에서 25m”라고 판정하면 실제로는 100m 밖일 수도 있습니다. 그래서 거리 30m와 정확도 30m를 함께 만족할 때만 판정하고, 둘 다 화면에 숫자로 보여 줍니다. 1일차 기능 검증에서 실제 노포 문 앞 측정값을 기록해 이 기준이 현장에서 통과되는지 먼저 확인합니다.

Q3 · Backend

Firebase를 추천합니다. Vercel은 웹사이트와 서버 함수를 올리는 곳이라, 로그인과 데이터베이스는 다른 서비스를 붙이고 API 코드를 직접 써야 합니다. Firebase는 안드로이드용 SDK가 로그인, 데이터베이스, 오프라인 동기화까지 한 번에 줍니다. 짧은 개발 일정에서는 이 차이가 큽니다.

v0.4에서 Firebase로 확정했습니다. 계정·평점·리뷰가 더해지면서 로그인과 데이터베이스, 오프라인 동기화를 한 곳에서 해결하는 장점이 더 커졌습니다. 앱은 Kotlin + Compose로 개발합니다.

Dev workflow

Android Studio + Claude Code로 개발하는 법

Claude Code가 코드를 쓰고, 빌드하고, 폰에 설치하고, 로그를 읽습니다. 사람은 폰에서 직접 눌러 보고 결과를 알려 주는 일과 변경 내용 승인을 맡습니다. BMAD 같은 별도 프레임워크는 설치하지 않습니다(이유는 아래 ‘BMAD를 쓸까’). 이 문서 묶음의 PRD·아키텍처·스토리·체크리스트가 같은 역할을 합니다.

준비내용
요금제Claude Code는 Pro·Max·Team·Enterprise 또는 Console 계정이 필요합니다. 무료 요금제로는 쓸 수 없습니다
설치Windows PowerShell irm https://claude.ai/install.ps1 | iex · macOS curl -fsSL https://claude.ai/install.sh | bash → claude --version
Android Studio플러그인 “Claude Code [Beta]” 설치 → 프로젝트 루트 터미널에서 claude → 변경은 IDE 비교 화면으로 확인
프로젝트 파일CLAUDE.md(작업 지침), .claude/settings.json(빌드·설치 명령 허용, 키 파일 읽기 차단), .claude/agents/nopo-qa.md(QA 서브에이전트)
요청문 틀“S-___ 를 구현해줘. 계획을 5줄로 말하고 진행, 테스트 먼저, 끝나면 빌드·설치하고 폰 확인 목록을 줘”

Q5 · Method

BMAD를 쓸까: 방식만 빌려 Claude Code로

전체 도입은 추천하지 않고, 방식만 빌려 쓰는 것을 추천합니다. BMAD는 분석가, PM, 아키텍트, UX, 스크럼 마스터, 개발자, QA 역할의 AI 에이전트가 문서를 차례로 넘기며 개발하는 오픈소스 방법론입니다. 좋은 방법이지만, 지금 이 기획안에 들어 있는 PRD, 아키텍처, 스토리 분할, QA 체크리스트가 바로 BMAD가 앞 단계에서 만들어 내는 산출물입니다. 그 단계를 다시 도구로 돌리면 짧은 개발 기간 중 반나절 이상이 설치와 문서 재생성에 들어갑니다. v0.4에서는 남은 개발 단계를 Claude Code가 맡고, QA 역할은 nopo-qa 서브에이전트와 실기기 확인이 맡습니다.

Q4 · Design tools

평가위원 눈에 띄는 UX/UI 만드는 법

평가위원이 “예쁘다”고 느끼는 지점은 화려한 그림보다 일관성, 빈 화면까지 챙긴 꼼꼼함, 한 번의 인상적인 순간입니다. 이 앱에서는 도장이 찍히는 순간이 그 한 번입니다. 아래 순서로 도구를 쓰면 혼자서도 이 세 가지를 갖출 수 있습니다.

① Google Stitch로 시안 뽑기

Google Labs의 AI 화면 디자인 도구입니다. 글로 설명하면 앱 화면을 한 번에 최대 5개까지 그려 주고, Figma로 보내거나 디자인 규칙 파일(DESIGN.md)로 내보낼 수 있습니다. 소개 자료 기준으로 Google 계정만 있으면 무료이며 월 생성 횟수 제한이 있습니다.

  1. stitch.withgoogle.com에 Google 계정으로 들어가 모바일 앱을 고릅니다.
  2. 아래 프롬프트를 붙여 넣습니다. 색 코드를 직접 주면 결과가 이 기획안과 맞게 나옵니다.
  3. 마음에 드는 화면을 고르고 “더 여백 넓게”, “도장을 더 크게”처럼 말로 고칩니다.
  4. Figma로 내보내거나, DESIGN.md를 내려받아 AI 코딩 도구에 같이 넘깁니다.
Android 앱 "노포 천년 미식가" 화면 5개: 지도(하단 시트), 가게 상세, 영수증 인증 카메라, 도장 획득 연출, 내 패스포트. 분위기: 오래된 골목 간판, 법랑 간판의 청록, 종이 영수증의 회녹색 바탕, 붉은 인주 도장. 색: 배경 #EDF0EA, 카드 #F8F9F5, 주색 #1F6B63, 간판 #17504A, 도장 #C23B2A, 보상 #D9A22C, 글자 #14201E. 글꼴: 큰 숫자와 제목은 굵은 한글 제목체(Black Han Sans 느낌), 본문은 Noto Sans KR. 가게 상세에는 업력 숫자 "62년"을 아주 크게, 버튼은 화면 아래 엄지 영역에. Material 3 기준, 모서리 16dp, 터치 영역 48dp 이상.

Stitch는 실험 단계 서비스라 기능과 무료 한도가 바뀔 수 있습니다. 결과물을 그대로 쓰기보다 방향을 잡는 용도로 씁니다.

② Figma와 Material Theme Builder로 토큰 고정

  1. Figma에서 Material Theme Builder 플러그인을 엽니다. 웹 버전(material-foundation.github.io/material-theme-builder)도 있습니다.
  2. 주색에 #1F6B63을 넣으면 라이트·다크 색 세트가 자동으로 만들어집니다. 도장 빨강은 보조색으로 직접 지정합니다.
  3. 내보내기에서 Jetpack Compose를 고르면 Color.kt, Theme.kt가 나옵니다. 이것을 그대로 프로젝트에 넣습니다.
  4. 이후 화면 코드에서는 색 코드를 직접 쓰지 않고 MaterialTheme.colorScheme.primary처럼 이름으로만 씁니다. 다크 모드가 자동으로 맞춰집니다.

③ Compose Preview로 모든 상태 확인

④ 도장 연출: Compose 애니메이션 + Lottie

도구쓰는 곳방법

Q7 · Build-up

빠져 있던 기획, 더하면 좋은 기획

지금까지의 기획은 사용자 한 명의 수집 경험에 집중되어 있었습니다. 평가에서 자주 나오는 질문은 “가게에는 무엇이 좋은가”, “부정 인증은 어떻게 막나”, “심사장에서 어떻게 보여 줄 건가”입니다. 이 세 질문에 답하는 기획을 더했습니다.

추가 기획내용왜 필요한가시점
테스트 가게진단 화면에서 현재 위치에 가상 가게를 만들고, 샘플 영수증·간판 이미지로 실제 인증 로직을 그대로 시험. 서버·프로필에는 남지 않음심사장은 노포가 아님. 우회 없이 실제 로직으로 시연첫 버전
세 번째 인증: 가게 QR협조하는 가게에 QR 스탠드를 두고, 찍으면 바로 인증영수증·간판보다 확실하고 사장님과 연결되는 고리확장
사장님 상생가게별 방문 수 통계, “천년 미식가 인증 노포” 스티커, 단골 혜택 등록“가게에는 무엇이 좋은가”에 대한 답확장
지역 컬렉션·시즌 퀘스트“을지로 노포 5곳”, “평양냉면 노포 도장첩”, 완성 배지다음 방문 이유. 구청·관광 기관 제휴 모델확장
사라진 맛 기록관폐업한 노포의 도장은 “기록된 가게”로 남기고 추억 한 줄 남기기노포가 사라지는 문제를 다루는 사회적 가치확장
오류 신고와 업력 검증 배지창업연도·위치 오류 신고, 공식 출처 확인 가게에 배지데이터 신뢰첫 버전(신고 링크)
오프라인 우선가게 목록을 앱에 포함, 인증 기록을 먼저 폰에 저장지하·골목 노포의 약한 전파첫 버전
개인정보 최소화좌표 대신 거리만 저장, 영수증 사진 비저장심사 질문 대비, 법적 부담 축소첫 버전
공유 카드세월·칭호를 담은 세로 이미지입소문확장
수익 모델 가설지자체 스탬프 투어 대행, 실물 패스포트 책자, 노포 굿즈 협업“어떻게 지속하나”에 대한 답발표용

Schedule

일정: 개발 4일(예비 포함) + 실기기 QA 1일

스토리 크기로 다시 더하면 개발이 약 43시간, QA가 8시간입니다. 하루 12시간이면 개발에 3일 반이 걸려, 4일차는 밀린 것을 흡수하는 예비 겸 개발일로 두고 5일차는 실기기 QA와 버그 수정에만 씁니다. 무결점 동작이 최우선이라 QA 시간은 줄이지 않습니다. 3일 안에 끝내야 하면 아래 컷라인을 처음부터 적용합니다.

APK 배포: 다른 폰에 설치하고 업데이트하기

단계할 일주의
1. 만들기./gradlew assembleRelease → app/build/outputs/apk/release/app-release.apk서명 키가 있으면 그 키, 없으면 디버그 키로 서명됨
2. 보내기구글 드라이브·메신저 등으로 APK 파일 전달, 파일 이름에 버전 표기내 폰은 USB 연결 후 adb install -r로 바로 설치
3. 설치 허용폰에서 파일을 열면 “이 출처의 앱 설치 허용”을 묻는 화면 → 허용 → 설치Play 프로텍트 경고가 뜰 수 있음
4. 업데이트versionCode를 올린 새 APK를 같은 방법으로 설치같은 서명 키여야 덮어 설치됨. 디버그 키 APK에서 정식 키 APK로 바꿀 때는 앱을 지우고 다시 설치(로그인하면 서버 기록 복원)
앞으로 바뀌는 것Google은 2026년 9월 30일 인도네시아·싱가포르·태국부터 ‘개발자 인증’을 받은 앱만 설치되게 하고, 2027년에 전 세계 인증 기기로 넓힐 계획입니다. 한국은 아직 첫 대상에 들지 않았고, ADB 설치는 계속 허용됩니다. 테스트 기기 20대까지는 신분증 없이 무료인 ‘제한 배포 계정’으로 인증할 수 있습니다.
