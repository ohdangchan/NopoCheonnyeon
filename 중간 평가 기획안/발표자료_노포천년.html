01 프로젝트 목표 · 기획 배경

"3일 안에, 폰에 설치해 모든 기능이 도는 앱을 만들 수 있을까?"

데모 영상이 아니라 설치되는 APK. 그러려면 기능과 안정성이 실제 기기에서 검증되어야 한다.

목표 1

실제로 가서 쓰는 앱

노포 앞에서 영수증을 찍고 도장을 받는 순간까지, 폰 하나로 끝나는 경험을 만든다.

목표 2

내가 쓰고 싶은 앱

내가 가 본 오래된 가게를 한눈에 모아 보고 싶다는 개인적 불편에서 출발한다.

목표 3

만들고 → 설치하고 → 고친다

실기기 QA와 자동 테스트로 결함을 먼저 잡고, 사용자 반응으로 다음 범위를 정한다.

04 방문 인증 규칙

영수증은 위치 없이, 안 되면 30m 안에서 가게 사진으로

경로판정 규칙개인정보 처리
① 영수증 인증(전화번호 일치) 또는 (상호 유사도 ≥ 0.70) 그리고 결제일시 24시간 이내 · 같은 영수증 해시 1회기기 안 글자 인식, 이미지는 판정 후 즉시 폐기, 위치 미사용
② 사진·위치 인증거리 ≤ 30m 그리고 정확도 ≤ 30m → 간판·메뉴판 글자에서 가게명(≥ 0.60) 또는 전화번호사진은 기기에만 저장, 좌표는 서버에 안 보냄, 모의 위치 거부
③ 위치 확인 도장글자 확인 3번 실패해도 30m 조건 통과 시 별도 표시로 기록한자·붓글씨 간판에서 막히지 않게
한도하루 5곳 · 같은 가게 하루 1회 (서울 자정 기준)몰아 찍기 완화
정확도도 30m. 정확도 ±80m인 위치로 "25m"라고 판정하면 실제로는 100m 밖일 수 있어, 거리와 정확도를 함께 본다.
기준값은 한 곳에. 인증 상수는 VerificationConfig에만 있고 현장 시험 후 여기만 고친다.
04 AI 도입 전략

기능마다 입력과 안전장치를 다르게 설계했다

기능기법모델핵심 설계
노포 도우미후보 압축 + 구조화 출력(JSON 스키마)Gemini flash-lite → 예비 모델앱이 후보를 먼저 골라 넘기고, 목록에 없는 가게 ID는 버림
메뉴 룰렛멀티모달(사진) + 제외 목록Gemini flash-lite이전 9라운드 메뉴를 제외, 최대 10번 = 서로 다른 메뉴 30개
후기 분석·충성도통계 기반 프롬프트Gemini flash-lite앱이 기준 점수를 계산하고 AI 보정은 ±12점으로 고정
촬영 도우미멀티모달 + 실패 사유Gemini flash-lite이미지 첨부, 한 문장 안내, 실패해도 인증은 막지 않음
처음 사용 전 동의. 영수증 글자·사진·후기가 외부 AI로 전송됨을 알리고, 동의 후에만 호출한다.
모델 이름은 한 곳. 모델 상수를 한 군데에 두고, 응답이 느리면 25초 뒤 예비 모델로 한 번 더 시도한다.

06 트러블슈팅 ① 영수증 인증 판정

영수증 양식이 제각각이어도 "패턴"으로 읽는다

문제해결왜
양식이 단말기마다 다름자리가 아니라 패턴(전화·날짜 형식, 사업자번호 체크섬)으로 추출. 요일 괄호·두 자리 연도도 인식위치로 찾으면 양식이 바뀔 때마다 깨진다
법인명과 간판 이름이 다름전화 일치 또는 상호 유사도 0.70, 카탈로그 별칭과도 비교정상 방문이 이름 차이로 막히지 않게
흐리거나 영수증이 없음첫 화면부터 "가게 사진으로 인증" 버튼, 실패 시 AI가 원인 안내한 번 탭으로 다른 경로로 전환
남의 영수증·재사용24시간 · 해시 중복 차단 · 하루 5곳완전 차단은 불가해 피해를 제한
06 트러블슈팅 ② 릴리스에서만 나는 문제

디버그에서는 되는데 릴리스 APK에서 깨지는 일들

증상원인과 해결배운 점
릴리스 앱이 시작하자마자 종료R8 최적화가 Crashlytics와 충돌(IllegalAccessError). 최적화는 끄고 축소·난독화만 사용(-dontoptimize)QA는 항상 릴리스 서명 APK로
내 위치가 늦게 잡힘마지막 위치를 먼저 쓰는 빠른 측정(quickFix)과 "내 위치" 버튼에 지도 재중심 추가실기기에서만 느껴지는 지연
리뷰를 쓰면 이전 리뷰가 사라짐문서 ID를 가게_사용자_슬롯(1~5)으로 바꿔 한 가게에 여러 리뷰데이터 모델을 요구사항 변화에 맞춤
도장 → 연출 순서가 어색함도장 찍힘 → 충격 고리 → 폭죽 → 칭호 승급 순서로 연출을 정리보상 순간에 연출 비용을 집중
06 트러블슈팅 ③ AI 호출 보안·안정성

공개 APK에 키를 넣지 않고도 AI가 그대로 동작하게

문제해결
키가 APK 안에 있음호출을 Firebase AI Logic으로 옮기고 키·BuildConfig 제거. APK 안에서 키 문자열 0건 확인
"App Check token is invalid"콘솔 APIs 탭에서 AI Logic 적용 해제 후 폰에서 응답 확인(반영에 약 10분)
모델이 붐벼 응답이 40초 넘게 멈춤요청 제한 25초 + 예비 모델로 한 번 더 시도, 단위 테스트로 고정
06 바이브 코딩 ① 설정 구조

AI에게 "알아서 해 줘" 대신 문서 · 규칙 · 역할을 줬다

3일 안에 설치되는 품질을 내려면 AI가 매번 같은 기준으로 일하게 만들어야 했다.

문서가 먼저. 판단이 애매하면 코드보다 PRD·아키텍처를 본다. 기준 우선순위는 PRD → 아키텍처 → 스토리 → 기획안 → 시안이다.
작게, 검증하며. 스토리 하나씩 구현하고 테스트·빌드·실기기 설치로 끝낸다. 새 라이브러리는 이유를 말하고 먼저 묻는다.
